# 長期任務詳情頁統一設計

## 目標

將孩子端長期任務詳情頁統一為同一套視覺與閱讀順序，並以「自主閱讀計畫」作為正式 Demo。頁面要讓孩子看見跨週累積、今天能做的下一步、最近形成的節奏與下一個里程碑，而不是呈現成一般打卡 App 或不同任務各自一套介面。

本次同時新增承恩的「自主閱讀計畫」Demo 資料，讓首頁能進入完整詳情頁並可供簡報截圖。

## 產品原則

長期任務的價值不是連續簽到，而是把模糊期待改寫成孩子能參與、能累積、能調整的計畫。

- 自主：孩子能選書，並在有需要時調整閱讀時段。
- 勝任：從每次 15 分鐘開始，總進度以實際承諾的閱讀次數呈現。
- 連結：週末共同回顧取代每天追問，家長仍保有調整與安全退路。
- 誠實：只呈現系統真的能保存和使用的選項。
- 低壓：完成後留下足跡；不以頁數、分數或每次發幣評價閱讀。

## 任務分類與進度策略

家長建立任務時看到的「學習與技能」是生活化分類，不代表孩子端必須顯示技能關卡。

「自主閱讀計畫」採用節奏型長期任務：

- 週一至週五進行。
- 每次閱讀 15 分鐘。
- 一共四週，總目標為 20 次。
- 第一週先尋找適合自己的閱讀節奏。
- 每週末共同回顧，必要時調整時段或支持方式。

其他長期任務仍可使用不同進度來源：

- 習慣型：完成次數與週期。
- 技能型：目前階段與總階段。
- 家庭型：參與次數或共同累積。

差異只影響資料、文字和進度計算，不再切換成不同視覺頁面。

## 統一頁面架構

移除獨立的 `SkillGoalView`、`HabitGoalView` 和 `FamilyRoleView` 畫面分支，改為單一 `LongTermGoalDetailView`。所有任務依序顯示：

1. 任務 Header。
2. 樹屋總進度 Hero。
3. 今天的小步驟。
4. 本週進度。
5. 旅程回饋。
6. 週末或階段回顧。
7. 固定底部導覽。

頁面透過 `GoalPresentation` 將不同任務資料轉換成共同元件需要的內容，例如總進度單位、今日行動、每週節點、回顧文案與里程碑。

## 視覺比例

以 `design-previews/long-term-reading-v3.html` 為實作基準。

- Header 高度約 68px，顯示任務名稱與目前週次。
- Hero 在手機寬度下約 194px，高度固定且不讓文字與素材重疊。
- Hero 使用首頁既有的 `treehouse-night.png`，不再使用房屋 emoji。
- Hero 左側保留樹屋場景，右側顯示分類、總進度、進度條、本階段重點與下一站。
- 主要卡片圓角約 18px，內距約 15px，卡片間距約 12px。
- 每張卡只承擔一個功能，避免卡片內再堆疊多層卡片。
- 文字與圖示在 360–430px 寬度內不可重疊或截斷。
- Web 延續滑鼠拖曳與垂直捲動支援。

## 自主閱讀計畫內容

### Header

- 標題：自主閱讀計畫
- 狀態：第 1 週

### 總進度 Hero

- 分類：學習與技能
- 總進度：`3 / 20 次 · 共 4 週`
- 百分比：15%
- 本階段重點：第一週，先找到適合自己的閱讀節奏
- 下一站：完成本週 5 次與週末回顧

新建立時顯示 `0 / 20 次`。進行中狀態依真實完成紀錄計算，不以 `current_day - 1` 推估。

### 今天的小步驟

- 行動：自己選一本喜歡的書，閱讀 15 分鐘。
- 預設時段：在家長確認計畫或週末回顧時設定。
- 詳情頁顯示「今天預計：晚餐後」。
- 孩子只有當天需要改變時才點「今天要調整」，可改為睡前。
- 主要按鈕為「完成今天閱讀」，不加入沒有後續作用的次要打卡選項。

完成後，按鈕改為「今天的閱讀已記下」，再顯示一個不影響獎勵的簡短問題：

- 我自己開始的。
- 提醒後開始。

這筆資料只用來支持週報中的「主動開始」與「提醒需求」，不做動機判定。

### 本週進度

只顯示週一至週五，避免把休息日顯示成未完成。

- 完成後顯示足跡。
- 自己開始使用星形狀態。
- 提醒後完成使用一般完成狀態。
- 今天與未到日期有明確但低刺激的差異。
- 摘要範例：「這週已閱讀 3 次，其中 2 次是自己開始的。」

### 旅程回饋

回饋與里程碑綁定，不為每次閱讀逐次發幣。

- 第一週里程碑：完成本週 5 次閱讀，閱讀樹亮起一片葉，成長幣 +10；週末共同回顧不作為領取門檻。
- 四週里程碑：完成整段計畫，和媽媽一起選下一本書或慶祝方式。

每日完成只留下足跡與溫和確認，避免把閱讀變成逐次換錢。

### 週末回顧

回顧問題聚焦生活節奏與關係：

- 哪一本最喜歡？
- 晚餐後還是睡前比較適合？
- 下週是否需要少一點提醒或恢復原本支持？

孩子端只顯示「和媽媽聊聊」入口，不顯示 AI confidence、SDT 判定或教養風格。

## 資料與互動

現有 `task_completions` 只能保存完成時間、回報者和獎勵，不能保存閱讀時段或開始方式。正式功能需要新增可空欄位：

- `long_term_goals.preferred_time_window`：`after_dinner` 或 `before_bed`。
- `task_completions.planned_time_window`：當天實際採用的時段。
- `task_completions.start_mode`：`self_started` 或 `reminded`。

完成任務仍使用既有 `complete_task` RPC。RPC 回傳 `completionId` 後，再透過受 RLS 保護的資料操作保存當次閱讀脈絡。脈絡紀錄失敗不可撤銷已成功的完成紀錄；介面應提示可稍後補記。

總進度與本週進度均由 `task_completions` 的真實紀錄計算：

- 總進度：此目標開始後的有效完成次數 / 20。
- 本週進度：當週週一至週五的完成紀錄。
- 自己開始次數：本週 `start_mode = self_started` 的紀錄數。

## Demo 資料

為承恩新增一筆可重複執行而不產生重複資料的 Demo 任務：

- 名稱：自主閱讀計畫
- 類別：學習與技能對應的既有任務類別
- 長期進度策略：habit
- 每次時間：15 分鐘
- 進行日：週一至週五
- 總目標：20 次
- 目前狀態：active
- 預設時段：晚餐後
- 第一週里程碑：第 5 次完成時發放 10 成長幣並亮起閱讀葉
- `checkpoint_rewards`：`{"5": 10}`

Demo 資料必須透過承恩的既有 child profile 關聯，不可硬編碼未知 UUID。若同名任務已存在，沿用並更新，不新增第二筆。

## 狀態與錯誤處理

- 載入中維持 Header 與底部導覽穩定，內容區顯示 loading。
- 任務或目標不存在時顯示可返回的錯誤狀態。
- 今天已完成時不可再次送出完成。
- 非進行日顯示「今天是休息日」，不顯示完成按鈕。
- 時段尚未設定時，不阻擋完成；顯示中性文字「今天可以自己選適合的時間」。
- 開始方式未回答時，完成紀錄仍有效。
- 里程碑回饋只在第一次跨越門檻時發放。

## 測試

- 所有長期任務類型渲染相同的共用區塊與樹屋 Hero。
- 程式碼不再渲染獨立 `SkillGoalView` 視覺。
- 閱讀計畫顯示 20 次總進度和週一至週五節點。
- 當天調整按下前不顯示兩個時段選項。
- 完成後才詢問自行開始或提醒後開始。
- 非進行日不顯示完成按鈕。
- Web ScrollView 保留滑鼠拖曳樣式。
- 360px、390px 與平板寬度下，Hero、卡片文字、進度節點和底部導覽不重疊。
- Demo 建立流程可重複執行且不新增重複任務。
